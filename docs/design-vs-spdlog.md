# 与 spdlog 的设计边界

minispdlog 的名称和部分常见工厂命名向 C++ 日志生态致意，分层思想也参考了 spdlog；但本仓库拥有自己的实现、测试、生命周期和功能组合。它不是 spdlog 的分支，也不是源码、ABI、API 或配置的 drop-in 替代品。

## 本项目自己的核心

minispdlog 当前把以下能力组合成一条可解释、可测试的数据路径：

- 同步 logger 与共享线程池异步 logger 并存；
- 可选阻塞 MPMC 与有界无锁 MPSC 后端，过载计数公开；
- logger Sink 拓扑写时复制，记录路径只读快照；
- 批量文件双缓冲、sidecar WAL 回放和换行断尾修复；
- 固定核心 schema 的 JSON Lines 与静态资源字段；
- Linux 内核 UDP/TCP 客户端、回环 listener 与可观测发送计数；
- callback 与可选 Qt 输出；
- 中文 Doxygen、行为测试和拆分式性能验证文档。

这些是本仓库代码的功能边界，不是对其他日志库“没有这些功能”的比较结论。项目独立性来自自己的约束和取舍，而不是通过未经测量的优劣口号建立。

## 不兼容项

| 维度 | minispdlog 当前约定 | 接入含义 |
|------|---------------------|----------|
| 命名空间 | `minispdlog` | 不能只替换链接库 |
| 头文件 | `minispdlog/*.h` | include 路径需要修改 |
| 构建目标 | `minispdlog`，安装导出名 `minispdlog::minispdlog` | CMake 依赖需要修改 |
| 版本 | `0.1.0` | 公开 API 仍可能演进 |
| 异步生命周期 | 进程级共享池；无池时同步退化；建议显式 `shutdown()` | 需要重新审查初始化与退出顺序 |
| 无锁后端 | 单消费者 MPSC，拒绝 `overrun_oldest` | 不能照搬其他队列策略 |
| JSON | 固定字段 schema，专用 wrapper 默认锁定 JSON formatter | 需要按本项目字段契约接采集器 |
| 耐久文件 | batch + WAL + 行尾修复，仅特定 Sink 使用 | 需要根据 durability 重新评估保证 |
| 网络 | 当前仅 Linux 真正实现 | 跨平台应用必须提供条件分支 |
| pattern | 只支持 [API 速查](api.md) 列出的标志 | 不能假设外部库的所有 pattern 标志存在 |

即使函数名看起来相近，异常、默认值、格式标志、线程安全与刷新语义也可能不同。迁移必须以编译、测试和输出验收为准。

## 迁移检查表

从其他日志库接入 minispdlog 时：

1. 列出实际使用的 Sink、pattern、异步策略和 registry 操作；
2. 用 [API 速查](api.md) 逐项映射，不存在的能力不要用同名猜测；
3. 明确 `_mt` / `_st` 所有权，决定是否允许多个工作线程重排输出；
4. 为每个异步 logger 选择队列后端与满载策略，并监控计数；
5. 校验 `flush()` 和 `shutdown()` 的退出顺序；
6. 若输出 JSON，按字段类型做解析测试；
7. 若依赖文件恢复，进行 WAL、断尾和断电模型的故障注入；
8. 在目标平台运行完整测试，再做应用负载基准。

## 复用与致谢边界

仓库直接依赖 `fmt`，测试使用 `doctest`，各第三方目录继续受其自身许可证约束。README 对 spdlog、fmt 和 doctest 明确致谢。

新增代码不应从外部项目整段复制后仅改命名；若合法复用任何实现或文档，应保留来源、许可证与必要版权声明。设计相似不等于实现可无条件复制。

## 演进原则

- 优先扩展现有 logger → formatter → Sink 分层；
- 新能力先写清错误、并发、刷新与平台语义；
- 不为了表面兼容引入无法验证的行为；
- 不用单一微基准宣称普遍性能优势；
- 破坏 schema 或生命周期的变化必须更新测试和文档。

内部取舍见[设计决策](design-decisions.md)，实际调用方式见[快速开始](getting-started.md)。
