# 项目边界与接入契约

本文定义 minispdlog 当前版本能做什么、不能保证什么，以及应用接入时需要验证哪些行为。边界来自仓库代码、测试和公开文档，不来自项目名称或宣传口号。

## 项目能力指纹

minispdlog 将日志系统拆成可独立说明的数据面、耐久面和控制面：

- 同步 logger 直接进入 Sink，适合低复杂度和明确返回边界的场景；
- 异步 logger 使用有界队列与工作线程，可选阻塞 MPMC 或单消费者无锁 MPSC；
- `block`、`overrun_oldest`、`discard_new` 使过载选择显式，并公开覆盖与丢弃计数；
- 批量文件采用双缓冲，可选择 sidecar WAL、换行断尾修复以及 `fflush` / `fsync` 档位；
- JSON Lines 使用稳定核心字段和静态资源字段，非法 UTF-8 会替换为 U+FFFD；
- 文本 pattern 提供 `%q` 单行安全正文、`%u` UTC RFC 3339 时间和 `%E` Unix 毫秒时间戳；
- Linux 网络 Sink 使用真实 UDP/TCP Socket，另有 callback 和可选 Qt 输出；
- 协程 Awaitable 在共享 FIFO 控制执行器上完成 `flush` / `shutdown`，不侵入逐条日志热路径。

这些能力共同构成项目自身的功能边界。新增功能应继续保持路径可追踪、策略可配置、结果可观察、行为可测试。

## 公开契约

| 维度 | 当前约定 | 接入含义 |
|------|----------|----------|
| 命名空间 | `minispdlog` | 业务代码显式依赖本项目类型和函数 |
| 头文件 | `minispdlog/*.h` | 按功能包含同步、异步、协程或网络头文件 |
| 构建目标 | `minispdlog`；安装导出名 `minispdlog::minispdlog` | CMake 通过目标传播包含目录和链接依赖 |
| 版本 | `0.1.0` | 公开 API 仍可能演进，升级需要跑回归测试 |
| 异步生命周期 | 进程级共享池；无池时同步退化；建议显式 `shutdown()` | 初始化、停止生产和退出顺序必须明确 |
| 无锁后端 | 单消费者 MPSC，拒绝 `overrun_oldest` | 工作线程数和过载策略必须匹配队列模型 |
| 协程控制面 | 单线程 FIFO；操作不可取消；可自定义恢复调度器 | 适合等待低频生命周期操作，不替代逐条异步日志 |
| JSON | 固定核心字段；专用 wrapper 默认锁定 JSON formatter | 采集器应按字段契约解析，不依赖字段文本顺序 |
| 耐久文件 | batch + WAL + 行尾修复仅由特定 Sink 提供 | 不应把耐久保证泛化到所有文件 Sink |
| 网络 | 当前仅 Linux 实现真实 Socket | 跨平台应用必须提供条件分支或降级路径 |
| pattern | 只支持 [API 速查](api.md)所列的标志 | 未列出的 `%` 标志按文档约定处理，不应靠猜测使用 |

## 不承诺的范围

- 不实现通用遥测 SDK、动态上下文传播或分布式追踪协议；
- 不保证所有 Sink 都具备 WAL、原子提交或断电不丢失能力；
- 不把协程控制接口等同于内核异步文件或网络 I/O；
- 不隐藏平台差异，也不在不支持的平台模拟网络写入成功；
- 不根据单一机器上的微基准承诺固定吞吐量或延迟；
- 不承诺自定义 Sink 永不阻塞，外部设备与网络超时由实现者负责。

## 接入检查表

1. 列出实际需要的 Sink、pattern、异步策略和 registry 操作；
2. 按 [API 速查](api.md)逐项确认接口、默认值与异常行为；
3. 明确 `_mt` / `_st` 的所有权，并决定是否允许多工作线程改变跨 logger 的完成顺序；
4. 为每个异步 logger 选择队列后端与满载策略，并监控池级计数；
5. 校验 `flush()`、`coro::flush()` 与 `shutdown()` 的调用和退出顺序；
6. 若输出 JSON，按字段类型、控制字符和非法 UTF-8 做解析测试；
7. 若依赖文件恢复，进行 WAL、断尾和故障注入测试；
8. 在目标平台运行完整测试，再用真实消息尺寸、Sink 和并发数建立性能基线。

## 依赖与复用边界

仓库直接依赖 `fmt`，测试使用 `doctest`，各第三方目录继续受其自身许可证约束。新增代码若合法复用外部实现或文档，必须保留来源、许可证与必要版权声明；仅改变命名不能形成独立实现。

## 演进原则

- 优先扩展现有 logger → formatter → Sink 分层；
- 新能力先写清错误、并发、刷新、取消和平台语义；
- 数据热路径与生命周期控制路径分别优化、分别测量；
- 不为了表面统一引入无法验证的行为；
- 破坏 schema、持久性或生命周期的变化必须同步更新测试和文档。

内部取舍见[设计决策](design-decisions.md)，实际调用方式见[快速开始](getting-started.md)。
